spans components by nature. Convention: [`../CONVENTIONS.md`](../CONVENTIONS.md). Last updated:

**Status** = the stream's lifecycle, not the session's focus: `open` (in progress) · `done`
(delivered; may have a small hand-off) · `closed` (abandoned/refuted) · `blocked` (needs input).
The continuation hook's notion of the **active** stream is *session-scoped* (which open stream this
session is driving — inferred, not a field here); see [`docs-authority`](docs-authority/README.md) P5.

| [2026-07-23-world-geometry](2026-07-23-world-geometry/README.md) | done | Establish **ONE canonical geometric model** and conform the code to it. Ratified with the user + confirmed by simulation: billboards drawn **parallel to the view plane**, ground at **65°** to it, **fictional height `z = sin65·(px.y − base)`** measured per-prim against that prim's own base, projection parameter `s = z_light/(z_light − z_point)` (pure heights ⟹ pure y), **x separable** (`G.x = light.x + s·(prim.x − light.x)`, never influences y), and **left/right y-equality** ⟹ a billboard's shadow is **one y calculation + two projected top x's + its own bottom corners**. The shadow code today runs a *different* leaning-card fiction (`2·tan65` vs `sin65`, ~4.7× apart) with `SHADOW_LIFT` papering over the seating — so "what is our geometry" has no single answer in the codebase. Blocks shadows-on-prims. |
