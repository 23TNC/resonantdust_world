# Simulation pipeline — implementation plan

Companion to [`simulation.md`](simulation.md) (the design). This is the *how* and the
*order*, grounded in the current code. Branch `0.2`.

A key grounding discovery reshapes the risk: **the subscription-blocking read mechanism
is exercised in Phase 1, single-shard.** The worker (`server_simulation`) reads actor
state from its SpacetimeDB subscription and blocks until `dirty==0` — that's the same
machine whether the actor is on the worker's own shard or another. So Phase 1 proves the
blocking-read primitive; the only thing Phase 2 adds is *a second shard's subscription*
(the volume/multi-DB question), not the mechanism itself. The spike shrinks accordingly.

## Topology — crates & binaries

| Piece | Now | After |
|---|---|---|
| **edge** | `server/` crate (WS + upstream SDK) | same crate, becomes `server_edge` (rename is the *last*, cosmetic slice — it churns `bindings/`, compose, `bin/rd`) |
| **master** | — | new `server_master/` crate: SDK client, one `bump` call per shard per tic |
| **simulation** | — | new `server_simulation/` crate: SDK client, the worker pool loop |
| **object_shard** | old bitemporal tables | tick pipeline (fresh tables; `free_things`/`pawns`/`debug_mover`/`presence` deleted) |
| **zone_shard** | old hot/cold tables | tick pipeline (same macro; `cold_zones`/`hot_*` deleted) |
| **shared/codec** | bit layouts | + entity-key pack/unpack |
| **shared/tick** | — | new: the `decl_tick_pipeline!` macro (module tables + reducers) **and** the pure worker-side helpers (priority hash, read-rule eval), so module and worker agree by construction |

The two shard classes run the **identical** generated pipeline — the only difference is
what the unified entity key decodes to. That's why the pipeline is a shared macro, not
copy-paste (follows the existing `decl_cell_history!` precedent in `zone_shard/hot.rs`).

## Unified schema (both shard classes)

State identity is the **entity key**, not `object_id`/`(zone_id,location)` separately —
so the tables are byte-identical across classes.

```
event_log:  event_reference u64 (auto_inc) | event_tic u32 | from_server_id u16
            | actor_shard_id u16 | actor_key u64 | target_key u64
            | action u16 | data [u64;2] | status u8
state_log:  entity_key u64 | tic u32 | dirty u16
            | kind u16 | zone_id u32 | location u8 | rotation u8 | offset u8 | data [u64;2]
            | server_id u16 | created_at u32 | assigned_at u32 | status u8   (PK: entity_key,tic)
state:      entity_key u64 | tic u32 | kind u16 | zone_id u32 | location u8
            | rotation u8 | offset u8 | data [u64;2]                          (PK: entity_key)
tic_meta:   id u8 (=0) | master_tic u32                                       (single row)
```

- `entity_key`: `[tag:2][OBJ: object_id:32]` or `[tag:2][ZONE: zone_id:32 | location:8]`
  (`shared/codec`). Object shards mint OBJ keys; zone shards ZONE keys. For an object,
  `zone_id`/`location` in the row hold *current position*; for a zone cell they're
  redundant with the key. Global uniqueness (the tag) is what lets `priority` be a total
  order across classes.
- `dirty`: `0` = resolved value; `>0` = pending (count is informational). One mutation
  per row (`N→0`), consumers gate on `0` → effectively immutable.
- `sequence` module (u16 tie-break) is retired — `event_reference` uses SpacetimeDB
  `auto_inc`. `time` module stays (wall-clock for `created_at`/`assigned_at`).

## Module reducers (generated by `decl_tick_pipeline!`)

All four are single-shard, atomic, and identical across object/zone shards:

- **`append_event(from_server_id, actor_shard_id, actor_key, target_key, action, data)`**
  — called by **edge**. Stamps `event_tic = master_tic + 2` (tic logic stays server-side;
  edge stays dumb) and appends to `event_log`. AoE = edge calls it once per target.
- **`bump(to_tic)`** — called by **master**. Idempotent (`to_tic == master_tic+1` or
  no-op). Sets `master_tic`; **work-gen**: scan `event_log where event_tic == to_tic`,
  group by `target_key`, upsert a pending `state_log(entity_key,to_tic,dirty=count)`
  (skip if already present); **promote**: copy `state_log where tic==master_tic && dirty==0`
  into `state`.
- **`claim(server_id, entity_key, tic)`** — called by **worker**. Sets
  `server_id`/`assigned_at` iff currently unassigned or lease expired; else rejects
  (loser backs off). The claim is the fence token.
- **`resolve(server_id, entity_key, tic, kind, zone_id, location, rotation, offset, data)`**
  — called by **worker** with the precomputed result. Checks `row.server_id == server_id`
  (fence) in-transaction; writes the row `dirty=0` + fields; marks its `event_log` rows
  `status=complete`; if `tic <= master_tic` promotes to `state`; the entity's frontier is
  now `tic` (max resolved `dirty==0` row). Rejects stale/evicted callers as a no-op.

## `server_master` binary

SDK client. Loop at `TIC_HZ` (config, default 2): `master_tic += 1`; call `bump(master_tic)`
on every shard, keeping them in lockstep (tic *N* means the same logical tic everywhere).
That's the whole binary. A coarse runaway guard (skip the tic if `master_tic` is already
`> min_frontier + K`) is the only backpressure.

## `server_simulation` binary — the worker loop

SDK client subscribed to `event_log` + `state_log` (its shard set). The loop:

1. **Discover**: pending rows (`dirty>0`, unassigned) in its shards → `claim`.
2. **Gather** (per held claim `(entity_key, tic)`): the target's `event_log` rows at `tic`
   (ordered by `event_reference`); for each event's `actor_key`, apply the **read rule** —
   ready iff the actor has no `dirty>0` row with `tic' ≤` the read tic — where the read tic
   is `tic` if `priority(actor) < priority(target)` else `tic-1` (**priority-DAG**,
   `priority = hash(tic, entity_key)`). Actor state comes from the subscription view.
3. **Park or resolve**: if any actor not ready, leave the claim parked (the subscription
   callback re-runs the loop when a row updates — reactive, no poll). Else **compose** the
   events (game-action dispatch on `action`) into the new state and call `resolve`.
4. **Catch-up**: after resolving `(entity_key, tic)`, if `tic < master_tic`, its `tic+1`
   is immediately claimable — the entity chases `master_tic`.

Determinism rules (invariant #10) are enforced here: integer math, RNG seeded from
`(tic, actor_key, target_key)`, no wall-clock in resolution. Action dispatch + the shared
read-rule/priority helpers live in `shared/tick`.

## Edge changes

- **`protocol.rs`** (server + `client/`): add `StateRow` wire type (an `entity_key`
  state), and a `Move`/generic-intent → `append_event` path. Drop `ColdZoneRow` /
  `HotCellRow` / `FreeThingRow` as their producers are deleted.
- **`ws.rs` / `connections.rs`**: subscribe clients to `state` (per anchored zone) and
  forward `StateRow`s; map inbound `Move` (and later actions) to `append_event`. Intent
  validation stays thin (well-formed, ownership) — the shared predicate from `shared/tick`.
- **`bindings/`**: regenerate for the new shard tables/reducers (`bin/rd` +
  `generate-bindings.sh object_shard|zone_shard`).

## Phase 1 — within-class, single shard (no cross-class subscription)

Each slice ships and is verifiable. Object shard first; the zone shard is the same macro,
so it comes nearly free once the object path works.

- **Slice 0 — foundations.** `shared/codec` entity-key pack/unpack (+ tests). `shared/tick`
  crate: the `decl_tick_pipeline!` macro (tables + the four reducers) and the pure helpers
  (`priority`, read-rule eval, action dispatch skeleton). Invoke it in `object_shard`;
  delete `free_things`/`pawns`/`debug_mover`/`presence` and the `sequence` module.
  *Verify:* module builds & deploys; tables exist; `bin/rd build/deploy module object_shard` green.
- **Slice 1 — master + tic.** `server_master` binary; `bump` advancing `master_tic` with
  work-gen + promote (no events yet). *Verify:* `master_tic` climbs at 2 Hz on the shard;
  bump is idempotent under a forced double-call.
- **Slice 2 — one action, end to end.** Action `move`. Minimal entity = a positioned
  object (`kind`, `zone_id`, `location`, `offset`). Edge `append_event(move)`;
  `server_simulation` claims → composes → `resolve`; edge forwards `state` to clients.
  *Verify:* an `npc`-issued move flows event→state→client; two clients see identical final
  position; provably no per-tic fan-out (idle entities write no rows).
- **Slice 3 — the hard semantics (local reads).** Add `damage` (reads target hp in `data`,
  reads actor). Implement the read rule + priority-DAG in the worker. All reads are
  same-shard here — but through the subscription-block path, so the blocking primitive is
  proven now. *Verify (the three acceptance tests):* (a) headless bots converge to
  identical state; (b) scripted mutual lethal exchange → higher-`hash` survives,
  deterministically; (c) scripted A→B→C chain → preemption (dead B doesn't hit C).
- **Slice 4 — worker robustness.** Claim contention (two workers, one wins), eviction on
  `assigned_at` timeout + re-assignment, fence rejects the late original, GC horizon =
  min frontier (soft-delete via `status`, hard-delete sweep). *Verify:* kill a worker
  mid-claim → work reassigned, no double-write; `event_log`/`state_log` bounded.
- **Slice 5 — zone shard.** Invoke `decl_tick_pipeline!` in `zone_shard`; delete
  `cold_zones`/`hot_*`. A `tile-change` action. *Verify:* a zone cell changes through the
  same pipeline; static cells cost nothing.

**In parallel with Phase 1:** the residual spike is now narrow — *can one worker hold
subscriptions to N shards and block across them at volume?* The single-shard block is
already proven by Slice 3, so this is a scaling probe, not a feasibility gate.

## Phase 2 — cross-class (gated on the multi-shard spike)

- Worker subscribes to a **second** shard; a `target_key` on shard X with an `actor_key`
  on shard Y resolves by reading Y's `state_log` via that subscription (same read rule).
- **Transfer/receive/ack saga** = object↔zone migration (attach/detach), re-introducing a
  `transfer`-style flow as *events* with the fixed ordering (receive first, ack last).
  This supersedes the old `transfer.rs` in both modules.
- Conserved-quantity debit/credit across shards.

## Legacy deletion checklist (as replacements land, not before)

- `object_shard`: `free_things.rs`, `pawns.rs`, `debug_mover.rs`, `presence.rs`, `gc.rs`
  (replaced by tick GC), `transfer.rs` (returns in Phase 2), `sequence.rs`.
- `zone_shard`: `zones.rs`, `hot.rs`, `transfer.rs`, `sequence.rs`, `gc.rs` (replaced).
- `server`: `ColdZoneRow`/`HotCellRow`/`FreeThingRow` protocol + their forwarding; the
  `move_debug_mover` binding path.
- `client`: `WorldBridge` projector + `TILE_TRAVEL_MS`; `ZoneTiles`/`ZoneThings`/
  `ZoneFreeThing` events replaced by state rows.
- `docs/sync.md` movement slices (Slice 0–4 there) are superseded by this plan.

## Micro-decisions surfaced by grounding (need a call before/within the slice)

- **Bindings for master/simulation** — per-crate generated `bindings/` (matches `server`)
  vs a shared `shared/stbindings` crate. *Lean:* per-crate now, dedup later.
- **`data [u64;2]` sufficiency** for entity state (hp + a few fields for Phase 1 — fine;
  confirm before a richer slice). Kind-specific interpretation lives in the action code.
- **Presence/routing** — Phase 1 is single-shard (default `db_name`), so `presence` and
  `index` region-routing are unexercised; keep `index` as-is, re-add presence-style routing
  only when multi-shard lands.
- **Edge rename** (`server` → `server_edge`) — do it last to avoid churning `bindings/`,
  `compose.yml`, `bin/rd` mid-build.
